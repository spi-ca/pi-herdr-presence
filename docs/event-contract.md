# Generic presence event contract

이 consumer는 process-local `pi-presence:update:v1`, `pi-presence:remove:v1`, `pi-presence:ready:v1`와 companion `pi-presence:summary:v1`만 소비하며 producer package를 import하지 않습니다.

`update`는 `{ version:1, sessionId, generation, sequence, source:{id,label,kind}, state, counts }`와 선택 `progress`, `usage`, `attention`을 사용합니다. state는 `idle`, `waiting`, `running`, `success`, `error`, `cancelled`, attention은 `none`, `info`, `success`, `error`입니다. text는 control/bidi 없는 1–96 code point, count는 0–1,000,000의 안전한 정수여야 합니다.

consumer는 같은 session ID만 수락합니다. source별 `(generation, sequence)`은 엄격히 증가하고 높은 generation은 **그 source만** reset합니다. 최대 64 source fence/value를 보관합니다. `remove`는 `{version,sessionId,generation,sequence,source:{id}}`이며 update와 같은 fence를 공유합니다. 수락된 remove는 retained value를 없애도 tombstone fence를 유지합니다. unknown source의 remove는 fence slot을 만들지 않습니다. producer는 same-process 협력 component라는 trust boundary 안에 있으며, bounded slot은 accidental/malicious slot 고갈을 완화할 뿐 인증을 제공하지 않습니다.

startup은 advertisement와 consumer-less ready request를 별도 frozen object identity로 emit합니다. own advertisement/request는 exact identity로 무시하고, external consumer-less ready request를 처리하는 동안 reentrancy guard를 유지합니다. 그러므로 synchronous observer가 ready를 재emit해도 advertisement/replay recursion이 생기지 않습니다. matching external request에는 advertisement 하나와 local/todo retained replay 하나를 보냅니다. replay attention은 `none`이며 advertisement는 replay를 만들지 않습니다.

`summary`는 독립 producer state가 아니라 이미 수락된 같은 `pi-subagent` `update`의 one-shot companion입니다. update/remove와 `(generation, sequence)` fence를 공유하므로 같은 update sequence의 summary는 한 번만 수락합니다. lower/older generation·sequence와 remove tombstone 뒤 stale summary는 거부합니다. newer update는 이전 retained summary를 즉시 withdraw하고 정확히 같은 새 sequence의 companion만 허용합니다. `summary`는 정확히 `{version,sessionId,generation,sequence,source:{id},active,omitted}`와 선택 `waiting`, `terminal`만 허용합니다. `active`는 최대 8개 `{id,agent,status:"running"|"cancelling",category:"active"|"cancelling",startedAt}`이고, `waiting`은 `{category:"queued"|"cancelling",count}`, `terminal`은 `{id,agent,status:"completed"|"failed"|"cancelled",completedAt}`입니다. text는 control/bidi 없는 1–96 code point, timestamp는 non-negative safe integer, count는 0–1,000,000이어야 합니다. raw task, output, error, path, socket, target 필드는 strict parser가 거부합니다. consumer는 ID/agent를 Herdr metadata나 notification에 복사하지 않고 count/category/terminal status/time만 최대 5 token으로 보냅니다. `failed` terminal만 error token을 설정하고 `completed`/`cancelled` status는 그대로 보냅니다. summary source의 generation 변경과 remove, session teardown은 retained summary와 terminal 보존 timer를 폐기합니다. terminal은 `(id,status,completedAt)` identity의 최초 수락 시점으로부터 `PI_HERDR_PRESENCE_FINAL_CLEAR_MS` 동안만 보존합니다. 반복/후속 summary는 deadline을 연장하지 않습니다. 이 identity expiry registry는 session별로 최초 수락 시 정한 original expiry를 고정해 유지하고, access 시에는 expiry를 연장하지 않고 recency만 갱신하는 최대 64개 access-order LRU입니다. teardown에서 초기화됩니다. registry에 남은 identity는 expiry 뒤 재등장하지 않지만, capacity 때문에 LRU로 먼저 제거된 identity는 다시 수락될 수 있습니다.

로컬 `pi`와 `pi-todo`는 예약 source입니다. `pi-subagent`를 포함한 external source는 retained composite state와 metadata count에 들어가지만 실행/취소/aggregate authority는 producer에 남습니다. `pi-subagent` terminal은 source generation 변경 또는 count reset에서 pending baseline을 폐기하며, 같은 generation burst의 최초 deadline(성공 450ms, error 100ms)을 연장하지 않습니다. notification dedupe는 source, generation, sequence, local turn과 attention category를 포함하므로 새 producer event나 다음 turn은 억제하지 않습니다. Dedupe는 TTL/LRU 최대 64개이며, errors/ask-user/blocked는 transition에서만 우선 처리하고 raw label은 전달하지 않습니다. local long-running은 turn당 unref timer 하나만 사용합니다.
