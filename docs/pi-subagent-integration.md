# pi-subagent generic producer integration

`pi-herdr-presence`는 `pi-subagent`를 dependency로 import하거나 실행/취소 authority를 갖지 않습니다. 같은 Pi process event bus에 [generic event contract](event-contract.md)를 발행하는 경우에만 정확한 `source.id: "pi-subagent"`를 cumulative terminal producer로 처리합니다.

consumer는 producer의 generation/sequence fence를 따릅니다. companion summary는 source가 정확히 `pi-subagent`인 이미 수락된 같은 `(generation, sequence)` `update`에 한 번만 붙을 수 있고 update/remove fence와 tombstone을 공유합니다. 따라서 older/lower generation, same-sequence replay, remove 뒤 stale summary는 수락하지 않으며, newer update는 이전 summary를 withdraw하고 같은 새 sequence companion을 기다립니다. generation 변경, 수락된 remove 또는 cumulative count 감소는 retained baseline과 pending terminal aggregate를 폐기합니다. 같은 generation의 terminal burst는 최초 event 기준 success 450ms/error 100ms deadline을 사용하며 뒤 event가 deadline을 sliding시키지 않습니다. producer payload의 label, task text, prompt, tool output은 Herdr notification text로 복사되지 않습니다.

discovery/replay로 retain한 snapshot과 새 session·새 generation·수락된 remove 뒤 initial baseline은 `attention: "none"`이다. 이는 actual first live terminal transition이 아니다. baseline 뒤 첫 live terminal transition은 `success` 또는 `error` attention일 수 있으며, 최초라는 이유만으로 `none`으로 낮추면 안 된다. `completed`, `failed`, `cancelled`는 generation 안에서 exact monotonic cumulative count다. producer의 bounded dedupe memory 또는 consumer의 bounded registry 때문에 count를 조용히 동결하거나 근사값으로 바꾸면 안 되며, count reset은 generation bump로만 한다.

선택 companion `pi-presence:summary:v1`은 정확히 `{version,sessionId,generation,sequence,source:{id:"pi-subagent"},active,omitted}`와 선택 `waiting:{category:"queued"|"cancelling",count}`, `terminal:{id,agent,status:"completed"|"failed"|"cancelled",completedAt}`를 보냅니다. active는 최대 8개의 running/cancelling 항목입니다. consumer는 strict parser로 raw task/output/error/path/socket/target field를 거부하고, parent pane에는 `subagents`, `subagent_wait`, `subagent_error`, `subagent_terminal`, `subagent_terminal_at`의 bounded 안전 요약만 기록합니다. `failed`만 error로 표시하며 completed/cancelled terminal status는 그대로 유지합니다.

`interaction`+`waiting` semantic profile은 input-needed이다. ordinary waiting은 working/queued 의미를 유지하며 input-needed로 나타내지 않는다. `waiting.category: "cancelling"` count에는 cancellation request만 존재하는 unit을 넣지 말고 cancelling이 입증된 work만 넣는다. aggregate cancellation은 aggregate의 active unit 전부가 cancelling임이 입증된 경우에만 나타낸다. 이 의미는 wire payload의 새 field나 version 없이 기존 `state`, `active`, `waiting` 조합으로 표현한다.

terminal `(id,status,completedAt)` identity는 최초 수락 deadline에서 `PI_HERDR_PRESENCE_FINAL_CLEAR_MS` 뒤 제거됩니다. 반복 summary는 deadline을 연장하지 않습니다. identity expiry registry는 session별로 최초 수락 시 정한 original expiry를 고정해 유지하고, access 시에는 expiry를 연장하지 않고 recency만 갱신하는 최대 64개 access-order LRU입니다. generation 변경, 수락된 remove, teardown은 retained summary, terminal timer, terminal identity expiry registry를 모두 clear합니다. registry에 남은 identity는 expiry 뒤 재등장하지 않지만, capacity 때문에 LRU로 먼저 제거된 identity는 다시 수락될 수 있습니다.
