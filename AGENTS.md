# pi-herdr-presence

`pi-herdr-presence` is a Bun Pi extension reporting TUI-only local presence through Herdr's supplied Unix socket. Use `bun@1.3.14`; run `bun run ci` before handoff.

Core invariants: require `HERDR_ENV=1`, absolute `HERDR_SOCKET_PATH`, explicit opaque `HERDR_WORKSPACE_ID`, and `HERDR_PANE_ID`; never execute a process/CLI/shell or open a Herdr subscription/stream (while subscribing to Pi lifecycle and shared V2 events); use one request per connection; validate identity, protocol, and socket paths strictly; keep failures output-only. The only recurring timer is the bounded workspace-summary lease.

`src/runtime.ts` owns lifecycle/V2 composition and output fences. `src/workspace-summary.ts` owns completion-relative lease pacing only; it must not own eligibility, serialization, or workspace clearing. `src/client.ts` owns mode-aware client sequencing and workspace eligibility; `src/protocol.ts` owns exact bounded envelopes; `src/transport.ts` owns socket framing, deadlines, and the bounded queue. `src/todo.ts` structurally traverses `params`/`error` within depth, field, and array-count bounds (not string-byte bounds), checks task count and allowed keys without traversing ignored task-field values, and semantically derives only IDs, statuses, and counts; it never copies, interprets, retains, or projects task text, arguments, or nested values. Required opaque pane/workspace IDs, the standalone session ID, and sequence, protocol, and terminal ordinals plus derived counts/tokens are distinct from arbitrary task/subagent content identifiers. `scripts/check-coverage.ts` is the CI coverage gate; `scripts/live-herdr-presence-producers.ts` is a manual, disposable standalone-only smoke harness.

Exact managed `herdr-agent-state.ts` presence selects companion coexistence: under `herdr:pi-presence`, applied to `herdr:pi`, it owns only the bounded fixed presentation and exact ten-token metadata projection, may emit policy-gated static notifications, and delegates aggregate accepted `ask_user` waiting transitions through one balanced in-process `herdr:blocked` lease. The managed integration remains the sole socket lifecycle reporter. Exact absence selects standalone `herdr:pi` authority. Unknown probes disable output. Neither mode clears workspace metadata; `main_summary` uses a 30-second expiry lease refreshed 10 seconds after completed attempts. `PI_HERDR_PRESENCE_METADATA=false` disables live pane metadata and workspace lease writes, not owned startup/teardown cleanup.

Test deterministic modules directly. Timer modules require an injectable scheduler and tests for completion-relative cadence, non-overlap, recovery, latest value, and stop fencing. Use local Unix-socket tests for transport/client/runtime integration behavior. Keep real-Herdr smoke code in `scripts/`, outside `test/`, guarded by exactly `PI_HERDR_LIVE_SMOKE=disposable-standalone-pane` with `PI_HERDR_PRESENCE_METADATA=true`, effective notifications disabled (prefer `PI_HERDR_PRESENCE_NOTIFICATIONS=false`), and `PI_HERDR_PRESENCE_FINAL_CLEAR_MS>=1000`; never add it to automatic CI. See `docs/architecture.md`, `docs/configuration.md`, `docs/event-contract.md`, and `docs/development.md`.
